Self-Stabilizing Plane: IMU + Barometer Fusion on STM32

A bare-metal embedded firmware project on an STM32F411RE Nucleo board that reads an MPU6050 IMU and a BMP280 barometric pressure sensor over a shared I²C bus, fuses that data into a live pitch/roll attitude estimate and altitude, and closes the loop with two PID controllers driving a pair of aileron servos toward wings-level, self-stabilizing flight. Written in C against the STM32 HAL, configured with STM32CubeMX/CubeIDE, with results streamed live over UART.

Pitch and roll come from the accelerometer's gravity vector via atan2, combined with angular rates from the gyroscope through a complementary filter (high-pass on the gyro, low-pass on the accelerometer), using a measured loop dt rather than an assumed constant, so the drift-corrected attitude estimate stays accurate regardless of loop timing. In parallel, the BMP280's raw pressure and temperature readings are run through Bosch's factory calibration/compensation formulas and converted to altitude with the standard barometric formula.

That filtered pitch/roll now feeds two independent PID controllers (roll: kp=3.3, ki=1.1, kd=0.5; pitch: kp=4.1, ki=0.8, kd=0.3), each computing derivative-on-measurement to avoid kick and clamping the integral term to prevent windup.

The two correction outputs are mixed elevon-style, adding and subtracting the roll term between two servo channels on TIM3 (PA6/PA7) so the ailerons move opposite for roll correction and together for pitch correction, driving the airframe back toward level. Getting the PWM right surfaced its own quirk: TIM3's configured prescaler/period give a real refresh rate of roughly 42 Hz rather than the textbook 50 Hz, close enough for most analog hobby servos but not exactly on spec.

This was a first embedded-systems project from scratch, and the debugging was as instructive as the result: tracing a bus that reported stuck-BUSY on the very first I²C transaction back to an unconfigured system clock, chasing intermittent NACKs to marginal breadboard connections, and working around a clone MPU6050 that reported the wrong WHO_AM_I identity byte.

What I Learned

Learned how to configure timers to generate PWM signals for hobby servos, how to implement a complementary filter for fusing accelerometer and gyroscope data, and how to implement PID control loops in embedded C. I also learned how to use the STM32CubeMX tool to configure peripherals and generate initialization code, as well as how to debug I²C communication issues and handle sensor calibration. Additionally, I gained experience in real-time embedded programming and the importance of timing considerations in control systems. I also learned how to effectively use UART for debugging and data streaming, which was crucial for tuning the PID controllers and verifying sensor readings. Overall, this project provided a comprehensive understanding of embedded systems, sensor fusion, and control theory in a practical application.

Challenges I Faced

The most challenging aspect of this project was that there was very little abstraction in STM32Cube requiring a strong understanding of the I²C protocol and how to implement it correctly in embedded C. I also had to learn how to properly configure the STM32 timers for PWM generation and how to tune the PID controllers for stable flight. Additionally, I faced challenges with sensor calibration and ensuring accurate readings from the MPU6050 and BMP280 sensors, which required careful attention to detail and iterative testing. The debug and bring up of the project was quite challenging as well as the address of the MPU6050 was different than listed on the datasheet which took a while to figure out.

What I'd Improve

If i was to do this proejct again and gave myself more time and had access to a 3D printer I would have designed a small plane in Solidworks and connected the servos to the ailerons and printed the plane to test the self-stabilizing flight. I would also have spent more time on the layout of the board.
